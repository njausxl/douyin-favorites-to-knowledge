# 抖音收藏 932 条，我给「自动转笔记」的流水线补上了两条看不见的通道

## 一、起因：笔记转出来了，正文却是空的

我用一套开源工具把抖音收藏夹自动同步成 Obsidian 知识库：采集 → 筛选 → 语音转写 → 写成 Markdown 笔记。

跑了大半年，攒下 932 条收藏、300 多篇笔记。直到某天随机点开几篇，发现不对劲：

有些笔记只有标题、作者、原始描述，正文一个字都没有；还有一些更离谱，正文是这种东西：

```
🎼你生看。
🎼嗯。。🎼的都荡。The number you dialed is not in service.
```

状态栏却明明白白写着 `success`。

查下去才发现，抖音的收藏里混着三类完全不同的内容，而这条流水线**只认识其中一类**。

## 二、先看结论

| 指标 | 数值 |
|---|---|
| 收藏总数 | 932 条 |
| 其中的图文帖 | 154 条 |
| 其中的抖音长文 | 38 条 |
| 补全后知识库笔记 | 366 条 |
| 含「图片文字 (OCR)」段落 | 122 条 |
| 含「文章正文」段落 | 35 条 |
| OCR + 长文提取总字数 | 约 24 万字 |

两大盲区已修复，并且**接进了主同步管线**——以后每次同步自动处理，不需要手工干预。

## 三、抖音的三类内容，和两个坑

抖音收藏里的内容，按 `aweme_type` 分三类：

| 类型 | aweme_type | 正文在哪 | 原来的处理 |
|---|---|---|---|
| 普通视频 | 0 | 音轨里 | 语音识别，正常 |
| 图文帖 | 68 | **图片里** | ❌ 完全丢失 |
| 长文（文章） | 163 | `article_info` 里 | ❌ 完全丢失 |

### 坑一：图文帖的「视频地址」其实是背景音乐

图文帖没有真正的视频流。抖音在 `video.play_addr` 字段里填的是**背景音乐 MP3**。

流水线不知道这件事，照常把这条 MP3 送去语音识别。ASR 对着纯音乐跑，于是输出了大段幻觉文本，状态还标成成功。

**结果就是：正文全在图片里一个字没抓，笔记里反而塞进了一堆噪声。**

### 坑二：长文正文被截断在 499 字

长文的正文藏在 `article_info.article_content.markdown` 里。但收藏列表接口返回的这份内容**被截断在 499 个字符**——那只是预览。

真正完整的正文，要走另一个接口才能拿到。

## 四、部署：先把环境搭起来

### 1. 前置条件

- Python 3.11 以上
- 上游项目 `douyin-favorites-to-knowledge`（Gitee 上的 tars123 版本）
- 一个 SiliconFlow 的 API Key（视觉模型按量计费）
- 首次采集需要扫码登录抖音，之后复用本地浏览器 profile

### 2. 安装上游项目

```bash
git clone https://gitee.com/tars123/douyin-favorites-to-knowledge.git
cd douyin-favorites-to-knowledge
python -m venv .venv
.venv/Scripts/pip install -e .
```

### 3. 打上补丁

补丁改 4 个文件，核心是给采集和转写两条链路加上新通道：

```bash
git apply patches/0001-ocr-and-article-support.patch
```

改动一览：

| 文件 | 改动 |
|---|---|
| `browser_collector.py` | 采集时多取 `item.images`；识别长文的 `article_id` 并调 `aweme/detail` 取全文 |
| `siliconflow.py` | 新增图片 OCR 通道；遇长文直接短路，不做语音识别 |
| `workflow.py` | 新增 `## 图片文字 (OCR)` 与 `## 文章正文` 两段渲染 |
| `cli.py` | 已入库的图文帖／长文从本轮剔除，跳过重复处理 |

注意：**`src/` 和 `.venv/Lib/site-packages/` 下面各有一份同名文件，两份都要打补丁**，否则重装依赖后改动会丢。

### 4. 装上技能包

把 `skill/` 目录整体拷到你的技能目录：

```bash
cp -r skill ~/.workbuddy/skills/douyin-image-post-ocr
```

### 5. 配好环境变量

```bash
export SILICONFLOW_API_KEY=你的密钥        # 只读环境变量，不落盘

# 代理没开的时候，这四行必须清掉，否则会报 ECONNREFUSED
unset HTTP_PROXY HTTPS_PROXY http_proxy https_proxy
```

视觉模型默认用 `Qwen/Qwen3-VL-30B-A3B-Instruct`，可以用 `DOUYIN_OCR_MODEL` 覆盖；`DOUYIN_OCR_ENABLED=0` 可一键关掉自动 OCR。

## 五、使用：四种进入方式

### 方式 A：日常同步，什么都不用管

补丁打完之后，`sync` / `daily` / `scan` 三条命令都会自动分流：

- 有 `images` 字段 → 走视觉模型 OCR
- 有 `article` 字段 → 直接取正文，**不消耗任何 API 额度**
- 都没有 → 照旧走语音识别

### 方式 B：存量图文帖批量补全

处理补丁上线之前入库的历史笔记，手工三步：

```bash
# 第一步：扩展采集，拿到完整的图片列表
python scripts/collect_images.py

# 第二步：批量 OCR（结果可断点续跑）
python scripts/ocr_images.py all Qwen/Qwen3-VL-30B-A3B-Instruct

# 第三步：回填笔记（先预演，确认无误再加 --apply）
python scripts/merge_ocr.py
python scripts/merge_ocr.py --apply
```

`--apply` 之前会自动整体备份知识库。

### 方式 C：把当初被误筛的图文帖捞回来

筛选收藏时如果用了「去掉游戏娱乐」这类口径，很容易连坐误伤。我这次就发现 81 条从没进过库的图文帖，其中 49 条其实是知识类内容。

这种情况**不要**走方式 B，直接复用主管线最省事：

```bash
python scripts/backfill_misfiltered.py plan   # 只打印名单，不发请求
python scripts/backfill_misfiltered.py run    # 执行，自动 OCR
```

### 方式 D：长文正文补全

```bash
python scripts/fetch_article_full.py          # 走 detail 接口取全文
python scripts/backfill_articles.py plan      # 预演
python scripts/backfill_articles.py apply     # 回填 + 入库
```

## 六、关键设计：三个必须绕开的坑

**一、OCR 结果不参与内容哈希。** 工具用 `content_sha256` 判断条目有没有变过。如果把 OCR 结果算进哈希，换个模型、换个措辞重跑一次，就会被判定成「条目已变更」而报错。所以 OCR 和长文正文都在哈希算完之后才挂上去。

**二、已入库的图文帖必须从本轮剔除。** 补丁上线前入库的图文帖，它的哈希是基于**背景音乐跑出来的噪声转录**算的。上线后跳过语音识别，就再也复现不出那个哈希，保留只会报错。剔除掉，既不报错，也省下一次付费 OCR。

**三、已入库笔记只能合并回填，不能重推。** 入库环节有一道「未跟踪笔记冲突」保护：笔记文件已存在、内容又和本次生成的不一致，就直接拒绝。所以删掉账本记录重新推是行不通的，必须用合并的方式把正文插进已有笔记。

## 七、实测数据

### 图文帖 OCR

| 验证项 | 结果 |
|---|---|
| 取样 | 6 条 / 145 张图 |
| 识别出文字 | 135 张（其余为纯风景照，正常） |
| 产出字数 | 30,386 字 |
| 端到端耗时 | 6 分 57 秒（约 2.9 秒/张） |
| 分流正确率 | 6 条全部走图片通道，无误送 |

最大的一条是 100 图的贴吧长帖，OCR 还原了 24,533 字，连楼中楼的评论都抽出来了。

误筛回捞那批：49 条 / 252 张图，25 分钟跑完，提取 73,844 字。

### 长文补全

| 验证项 | 结果 |
|---|---|
| 长文总数 | 38 条 |
| 回填正文（已入库） | 24 条 |
| 新增入库 | 11 条 |
| 正文合计 | 136,850 字 |

长文这条通道**零 API 成本**，因为它取的是抖音自己的正文，不用调模型。

### 模型选型

| 模型 | 表现 |
|---|---|
| PaddleOCR-VL-1.5 | ❌ 社交截图场景反复退化，输出一长串 0000 或 emoji 直到撞满上限 |
| Qwen3-VL-30B-A3B-Instruct | ✅ 干净还原正文、楼中楼评论、表格结构 |

**别迷信「专用 OCR 模型」**，在社交截图这个场景上，通用视觉模型反而更稳。

## 八、常见问题

**报 `promoted item changed`**：已入库条目的哈希对不上。图文帖走剔除逻辑即可；其他情况说明笔记被手工改过而账本没同步，需要人工迁移。

**报 `connect ECONNREFUSED 127.0.0.1:7890`**：环境里残留了没在运行的代理配置，`unset` 掉所有 proxy 变量再跑。

**图片下载失败 `IncompleteRead`**：抖音 CDN 偶发断流，重跑该条即可，已缓存的图片会自动跳过。

**怎么判断一条是不是图文帖**：看 `play_url` 是不是指向 `obj/ies-music` 并且以 `.mp3` 结尾——是的话，几乎一定是图文帖。

**入库前要不要脱敏**：要。安全校验会拦截疑似密钥、特定标记符号等敏感串。技术类长文里可能有代码示例，入库前先扫一遍。

## 九、写在最后

这套补丁本质上解决的是一个**字段语义误判**问题：工具以为所有收藏都有一条「视频地址 + 音轨」，但抖音的内容形态早就不是这样了。

图文帖的正文在图片里，长文的正文在文章接口里，两者都不在音轨里。把这两条通道补上，932 条收藏才算真正被读进来。

技能包和补丁已经开源，仓库地址见文末。如果你也在用类似的收藏自动整理流程，可以对照检查一下——你的知识库里，可能也躺着几十篇只有标题的空笔记。
